面向目标：12 周内从零到能独立做出并部署一个可用的 AI Agent 系统，同时攒出一份能写进简历的作品集。

> **v2 改了什么**：删掉全部课程、视频、搜索关键词，不再安排任何"看课"时段。学习输入只剩三种——官方文档、报错信息、你自己跑出来的数据。旧版留在 `agent学习路线-v1-存档.md`。

## 〇、这份路线怎么用

- 总周期 12 周，每周投入 10–15 小时（工作日每天 1–1.5 小时 + 周末 4–6 小时）。

- 硬件不设门槛：能调 API 就能学。本机 RTX 4060 8G 可额外跑 7B 量化模型，属加分项。

### 第 1 周 · Python 工程化与 API 调用

**进度**：

**动手任务**：

**卡住时查什么**：httpx 官方文档（Timeout / Retry 章节）、`logging` 标准库文档、Python 官方中文文档。

### 第 2 周 · LLM 基础与 Prompt 工程

**本周产出**：zero / few / CoT 三种写法的对比表（成功率 + token 成本 + 延迟）+ 一份提示词注入实验报告。

**已完成（真实数据，`week02_prompt_lab`）**：

| 写法 | 成功率 | 平均 prompt token | 平均 completion token | 平均延迟 |
|---|---|---|---|---|
| zero | 90.0% | 368 | 127 | 1243ms |
| few | 85.0% | 518 | 105 | 1096ms |
| cot | 40.0% | 372 | 198 | 1523ms |

**失败归因（比成功率重要）**：三组共 17 条失败，**全部是格式/约束违规**（`keywords` 超过 5 个、单个关键词超 20 字符、`contributions` 只给 1 条），
**抽取类错误（年份错、作者数错）为 0**。也就是说：模型能力没问题，瓶颈在提示词与 schema 设计。

**待修的 5 处（改完重跑，这张表才成立）**：
1. `runner.py` 的 CSV 加 `content` 列——现在失败样本无法复盘。
2. 拆开 `judge()` 的短路：schema 一挂就把 `year_ok`/`authors_ok` 也置 0，三个指标绑成一根绳。
3. `few.txt` / `cot.txt` 补回字段约束（`contributions` 2~4 条、`keywords` ≤5 个且每个 ≤20 字符）——现在约束只写在 schema 里，模型不知道。
4. `summary.json` 改成累积写，或每次统一 `--prompt all`（现在每次覆盖，只剩最后一次）。
5. README 里 `--out results/zero.csv` 这条命令不存在，改成 `--out-dir`。

**动手任务**：
1. 修完上面 5 处，重跑 `--prompt all --limit 20`，把新数字填进对比表。
2. 自己往 `samples.jsonl` 追加 10 条**难样本**（无年份、中英混排、超长摘要、格式混乱），看成功率怎么崩。
3. 从 arXiv 抓 20 条**真实**英文摘要（`export.arxiv.org/api/query?search_query=cat:cs.CL&max_results=20`），自己标 `expected`，加 `source` 字段。对比"合成集 vs 真实集"的成功率落差——这个落差就是结论。
4. 提示词注入实验：`injection_exp.py`，先不带防御跑一遍，截图模型被带偏的原话；再换 `defense.txt` 跑一遍。
5. 加分：同一批样本连跑 3 次，测 `temperature=0` 下的结果波动。

**必须能讲清的概念**（不看课，卡住就查文档，讲不清就说明没学会）：
token 怎么算钱 / 上下文窗口 / temperature 与 top_p 的分工 / system 与 user 角色差异 / `response_format` 能保证什么、不能保证什么 / 幻觉的成因与抑制 / 为什么 schema 约束必须同时写进提示词。

**三条教训（本周亲历，写进 README）**：
- schema 是给校验器看的合同，提示词是给模型看的说明书——**每一条硬约束都要写两遍**。
- 阈值必须按数据分布定：`maxLength: 20` 按中文关键词设计，英文多词短语（21、32 字符）必然越界。
- 指标不独立，等于没有指标。

## 三、阶段二（第 4–6 周）：单 Agent 核心能力

### 第 4 周 · RAG 检索增强

**产出**：能基于自己的资料回答、并给出可追溯引用的问答系统 + 三档 chunk 长度对比表。

**动手任务**：
1. 把自己的讲义/笔记做成知识库，实现带出处的问答。
2. 对比 chunk 长度 256 / 512 / 1024 对回答质量的影响，出表。
3. 在纯向量检索上叠 BM25 混合检索 + rerank，量化命中率提升。
4. 加分：处理"资料里没有答案"，要求模型明说"资料中没有"而不是编造。
5. 加分：统计检索命中率而不是靠感觉——建 20 条"问题→应在哪个 chunk"的标注。

**卡住时查什么**：Chroma 官方 Quickstart（20 行能跑起来）、`rank_bm25` 的 README、embedding 模型的输入长度限制。

### 第 5 周 · 记忆与状态管理

**产出**：跨会话生效的长期记忆 + 上下文压缩前后对比数据。

**动手任务**：
1. 给第 4 周助手加长期记忆，记住用户偏好并**跨会话生效**。
2. 实现自动摘要压缩（超 N 轮触发），比较压缩前后回答质量与 token 成本。
3. 做"错题本"：答错的题被记录，同类问题下次自动规避。
4. 加分：多会话隔离——两个用户同时用，记忆不串。

**卡住时查什么**：向量库的 upsert/query 接口、`sqlite3` 标准库（存事实的最省事办法）。

### 第 6 周 · 评测体系与提示词优化

**产出**：30 条评测集 + 一份带基线对比的评测报告。

**动手任务**：
1. 给自己的 Agent 建 30 条评测集（至少 5 条恶意注入、5 条边界问题），跑出基线。
2. 改一版提示词或换模型，重跑，出前后对比表。
3. 用 LLM-as-a-Judge 自动打分，人工抽检 10 条验证裁判可靠性，写结论。
4. **失败分类法**（本周必须掌握）：把每条失败归入 A 抽取错误 / B 格式约束违规 / C 基础设施错误，统计各类占比。占比决定优化方向。

**卡住时查什么**：`pytest` 官方文档（把评测集写成测试）、`csv`/`json` 标准库。

## 八、每周节奏模板与自检

### 时间分配（全动手，无看课时段）

- 周一至周三：每天 1–1.5 小时写代码 / 改代码。
- 周四至周五：每天 1–1.5 小时跑实验、看数据、补边界情况。
- 周六：3–4 小时集中调试 + 填数据表 + 写 README + commit。
- 周日：1 小时复盘（只回答下面四个问题，不安排新内容）。

### 卡住规则

任何问题超过 **40 分钟**没进展：查官方文档 10 分钟 → 把完整报错（含最后一行 `File "...", line N` 和错误类型）交给 AI 要**最小提示** → 记进"卡点清单"。不要在同一处死磕两小时。

### 每周日自检（必须回答，写进笔记）

- 代码能跑吗？README 别人照着能跑通吗？
- 这周学到的概念，不看资料能讲给别人听吗？
- 这周拿到了哪些**数字**？（没有数字就等于没做实验）
- 卡在哪里？怎么解决的？（面试时最值钱的素材）

## 九、常见坑（提前避开）

- **只跑不分析**：跑出 90% 就收工，等于白花 token。数字必须配上"为什么"。
- **指标不独立**：schema 一挂就把所有字段判失败，让你永远不知道模型到底弱在哪。先保证每个指标独立可测。
- **schema 与数据打架**：用想象定约束（"每篇论文肯定有 2 条以上贡献"），跑起来才发现 3/20 的样本不满足。先看数据分布，再定约束。
- **约束只写一半**：写进 schema 却没写进提示词，模型不可能遵守一个没被告知的规则。
- **对比实验变量没控住**：改提示词时同时改了示例和字段说明，得出的结论没有意义。一次只改一个变量。
- **不落盘原始输出**：只存指标不存模型原文，失败样本永远无法复盘。
- **一上来就上多智能体**：单 Agent 都跑不稳，多智能体只会放大混乱。
- **迷信框架**：先手写 ReAct 再用 LangGraph，才知道框架替你做了什么。
- **不看成本**：第 9 周必须做出成本看板。
- **只做 demo 不部署**：能让别人跑起来，才是工程能力的证明。
